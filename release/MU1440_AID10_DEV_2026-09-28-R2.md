## New in R2: foreign Java state handling

The installer now inventories existing LSD bootclasspath/Java patch state before replacing anything.

If a foreign/older state is found:

1. the current `lsd.sh`, recognized backups, JARs and hashes are archived on the SD;
2. `install.sh --check` exits with `PREFLIGHT=ATTENTION` and does not mutate target-side Java state;
3. `install.sh --apply` asks:
   - `C` — continue after archive, normalize the conflicting Java startup state and use the exact NavIgnore;
   - `Q` — abort without changing target-side Java state;
4. before `C` can mutate Java state, the installer proves that the final exact NavIgnore is already
   active or available as the exact replacement payload;
5. the complete preflight is rerun after normalization before the normal deployment proceeds.

Known DirectVCPolicy, Most20FPS and legacy combined `NavActiveIgnore.jar` states are covered. The old
dynamic "append all JARs" style is only normalized when a clean pre-Java `lsd.sh` backup is available;
otherwise the installer stops rather than guessing.

## New in R2: SD issue logging

Every top-level:

- `install.sh`
- `status.sh`
- `uninstall.sh`

creates a timestamped directory under:

`mhi2-altscreen-logs/`

It contains:

- `session.log` — complete stdout/stderr including hash mismatches and abort reasons;
- `vehicle-summary.txt` — sanitized train/MU/version/board context plus relevant file/JAR hashes;
- `archive/` — local recovery copies when foreign Java state is encountered.

The summary intentionally does **not** collect VIN, FAZIT or device serial numbers.

For a public GitHub Issue, `session.log` and `vehicle-summary.txt` are the intended default
attachments. Review `archive/` before sharing it: it may contain copied third-party/OEM JAR bytes.

## Standalone SD behavior

- ZIP contents go directly into the SD-card root;
- no `esd/` wrapper;
- no `MHI2AltScreen/` wrapper;
- bundled QNX ARMv7 `sha256sum`;
- bundled QNX ARMv7 `tee`;
- no runtime dependency on M.I.B. `config/BASICS`, `apps/mounts` or `/apps/sbin`;
- no runtime `sed`/`tr` dependency;
- SD/USB medium is explicitly remounted writable and write-tested;
- installed Auto-Direct runtime remembers that media root for persistent logs and falls back to
  `/tmp` if the medium is not yet available during boot.

## Deliberately excluded

- SafeArea-capable GEN2 candidate;
- dynamic ViewArea experiment;
- DirectVCPolicy / Most20FPS experimental Java policy builds;
- legacy combined Java patch.

The current D2 same-session keyframe policy remains an explicit developer switch while its watchdog
timing is still being tuned.

## Suggested first test

1. Extract the ZIP directly to SD root.
2. Add the exact NavIgnore to `payload/` unless it is already active with the exact hash.
3. Run `./install.sh --check`.
4. If it reports a foreign Java state, inspect the generated SD log/archive.
5. Run `./install.sh --apply` and choose `C` only if the archived state is understood and a recovery
   route is available.
6. Reboot.
7. Run `./status.sh`.
8. Confirm STOCK VC behavior before testing CarPlay Auto-Direct.

This remains a developer prerelease. The media-path binary bytes are vehicle-tested; the integrated
R2 installer/logging/foreign-Java recovery workflow is the part entering broader vehicle validation.
