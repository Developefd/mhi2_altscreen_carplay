# Support and triage

This is an experimental reverse-engineering project, not an end-user product.

## Use Discussions for

- architecture questions;
- exploratory reverse engineering;
- "has anyone seen this firmware?" questions;
- early vehicle test observations;
- hypotheses that are not reproducible yet;
- provider-switch observations;
- ViewArea ideas.

Recommended category: **Vehicle testing** for new hardware/firmware observations.

## Open an Issue for

- a reproducible bug in project-owned source/scripts;
- a repeatable vehicle regression with artifact hashes;
- a build failure;
- a documented research claim that is contradicted by reproducible evidence.

## A useful vehicle report includes

- firmware train / MU;
- relevant stock binary hash;
- project artifact SHA;
- exact command/test sequence;
- expected vs observed result;
- sanitized logs.

Before posting any log, screenshot or vehicle information, follow the redaction/privacy rules in [SECURITY.md](SECURITY.md). That file is the canonical policy for credentials, identifiers, locations and security-sensitive findings.

## Screenshots

Screenshots are optional. For this project, logs, counters and hashes are often better evidence and easier to sanitize.

If a screenshot is genuinely useful, crop/redact it according to [SECURITY.md](SECURITY.md) before posting.

## Security issues

For vulnerabilities that should not be disclosed publicly before a fix or mitigation is available, use the responsible-reporting process in [SECURITY.md](SECURITY.md).
