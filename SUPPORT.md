# Support and triage

This is an experimental reverse-engineering project, not an end-user product.

## Use Discussions for

- architecture questions;
- exploratory reverse engineering;
- "has anyone seen this firmware?" questions;
- early vehicle test observations;
- hypotheses that are not reproducible yet;
- provider-switch observations;
- ViewArea ideas.

Recommended category: **Vehicle testing** for new hardware/firmware observations.

## Open an Issue for

- a reproducible bug in project-owned source/scripts;
- a repeatable vehicle regression with artifact hashes;
- a build failure;
- a documented research claim that is contradicted by reproducible evidence.

## A useful vehicle report includes

- firmware train / MU;
- relevant stock binary hash;
- project artifact SHA;
- exact command/test sequence;
- expected vs observed result;
- sanitized logs.

## Privacy

Do not post:

- VIN;
- home/work/navigation addresses;
- credentials;
- Wi-Fi keys;
- SSH private keys;
- private account identifiers.

## Screenshots

Screenshots are not required for technical credibility.

For this project, logs/counters/hashes are often better evidence because navigation screenshots can
reveal precise location.

## Security issues

Use the process in `SECURITY.md` for vulnerabilities that should not be disclosed publicly before
a fix/mitigation is available.
